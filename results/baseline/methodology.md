# Методология эксперимента baseline v1

```text
Legal corpus
  → Structure-aware chunking
  → QA alignment и repair gold labels
  → Frozen clean TRAIN / DEV / TEST
  → BM25 hard-negative mining на TRAIN
  → BGE-M3 LoRA
  → Выбор эпохи по DEV
  → RRF для BM25 и плотного поиска
  → Оценка пяти методов на TEST
```

## 1. Юридический корпус и разбиение на чанки

Из `kz_legal_parallel.jsonl.gz` обработано 20 000 двуязычных записей. Разбиение учитывает структуру документа. Основные границы определялись по обозначениям статей наподобие «Статья N.» и «N-бап.». Для фрагментов без подходящей структуры использовались границы абзацев. Максимальный размер чанка составлял 2 500 символов. В `data/legal_chunks_20k.parquet` находится 305 375 чанков, из них 156 760 RU и 148 615 KK. Чанк хранит текст и ID, ID документа, язык, а при распознанной статье также её номер и заголовок. [Исходный юридический корпус](https://huggingface.co/datasets/kurumikz/kazakhstan_legal_corpus)

## 2. Выравнивание QA и исправление эталонной разметки

Исходный QA-набор после разворачивания содержал 13 159 строк. Связь с юридическими документами проверялась по идентификаторам источников, поскольку названия в метаданных QA могли ошибаться. Исходное разбиение выполнялось по `context_id`, чтобы связанные вопросы оставались в одном сплите. [Исходный QA-набор](https://huggingface.co/datasets/olzhasAl/adilet-legal-qa-kz)

Длинный QA-контекст нередко охватывал несколько статей, тогда как вопрос относился к одной норме. Первичная привязка к чанку иногда выбирала соседнюю статью. Это делает правильное извлечение похожим на промах по метрике и может подавать нерелевантный чанк как положительный пример при обучении.

1. Нормализуются Unicode NFKC, варианты дефисов и номера статей. Приоритет отдаётся вопросу с ровно одним уникальным номером статьи. Если в вопросе номера нет, можно использовать единственную статью из ответа. При нескольких номерах в вопросе целевая статья остаётся неопределённой.
2. Кандидаты ограничиваются одновременно `document_id` и `language`. При наличии точной статьи список дополнительно ограничивается её номером.
3. Внутри списка кандидатов выбирается лучший чанк по взвешенному косинусному сходству. Итоговый балл — `0.45 × sim(answer) + 0.30 × sim(context) + 0.25 × sim(question)`. Для выравнивания применяется символьный TF-IDF с `analyzer=char_wb`, n-граммами 3–5, `min_df=2`, `max_features=150000` и `sublinear_tf=True`. Общий TF-IDF подгонялся по текстам чанков-кандидатов и вопросам, ответам и контекстам всех трёх исходных сплитов. Он применялся только для построения эталона до заморозки бенчмарка.

## 3. Clean frozen benchmark

В итоговых сплитах учитываются только строки с `used_article_filter=True`. Для статей из вопроса требуются оценки сходства с ответом и контекстом не ниже 0,30. Для статей из ответа дополнительно требуется сходство с вопросом не ниже 0,10. `gold_relevant_chunk_id` берётся из `repaired_chunk_id`. Заморожены 1 087 TRAIN, 122 DEV и 268 TEST. Копии трёх скриптов подготовки и контрольные суммы хранятся вместе с данными. [Состав и хеши frozen](reproducibility.md)

## 4. BM25 и трудные негативы

BM25 строится по языкам. Токенизация использует NFKC, нижний регистр, нормализацию дефисов и Unicode-слова. При оценке параметры `BM25Okapi` равны `k1=1.5`, `b=0.75` и `epsilon=0.25`.

Для майнинга негативов строились отдельные BM25-индексы по языкам на 2 932 чанках шести документов, представленных в clean TRAIN, с дедупликацией по `chunk_id`. В индексе майнинга было 1 653 чанка RU и 1 279 KK. Из пула топ‑50 для запроса пропускались первые 3 кандидата. Затем отбрасывались эталонный чанк, его точный дубликат, чанки той же статьи того же документа, кандидаты с долей токенов ответа в чанке от 0,55 и повторно выбранные ID негативов. Из 1 087 строк TRAIN получилось 1 086 записей с одним позитивом и тремя негативами. Языковой состав после майнинга — 919 RU и 167 KK.

## 5. Плотный поиск и LoRA

Zero-shot использует закреплённую ревизию `BAAI/bge-m3`. Запрос и чанк кодируются одним XLM‑R энкодером. Плотное представление — нормализованное скрытое состояние первого токена CLS. Скалярное произведение двух таких векторов равно их косинусному сходству. Для LoRA с той же схемой кодирования использовалась контрастивная кросс-энтропия по четырём чанкам записи, где позитив занимал класс 0. Логиты сходства делились на температуру 0,05. [Плотное представление BGE-M3](https://bge-model.com/bge/bge_m3)

| Параметр прогона | Значение |
|---|---|
| LoRA rank / alpha / dropout | 16 / 32 / 0,05 |
| Целевые слои | `query` и `value` во всех 24 слоях XLM‑R |
| Обучаемые параметры | 1 572 864 веса адаптера, `bias=none` |
| Оптимизатор / learning rate / weight decay | AdamW / `2e-5` / 0,01 |
| Scheduler / warmup / gradient clipping | линейный / 10% запланированных шагов / норма 1,0 |
| Микробатч / накопление градиента | 1 запрос с 4 чанками / 8 запросов |
| Максимум токенов | 128 для запроса и 320 для чанка |
| Evaluation batches | 16 запросов и 8 чанков |
| Устройство / точность | MPS / FP32, SDPA |
| Gradient checkpointing | включён, `use_reentrant=False` |
| Максимум эпох / patience / seed | 5 / 2 / 42 |

## 6. DEV и выбор чекпойнта

Эпоха 0 фиксирует zero-shot перед обучением. После каждой эпохи LoRA оценивается на тех же 122 запросах DEV и в том же корпусе кандидатов. Критерий — строгое улучшение общего Recall@10. При равенстве сохраняется более ранняя эпоха. Эпохи 0 и 1 дали 0,9754, эпохи 2–4 дали 0,9918. Эпоха 2 первой достигла 121 попадания из 122 и была зафиксирована после остановки на эпохе 4. Средний train loss хранится для эпох 1–4. [История по эпохам](dev_history.csv)

## 7. Гибридное ранжирование RRF

Для каждого чанка суммируются два вклада, по одному от BM25 и плотного ранжирования. При позициях `r_BM25` и `r_dense`, нумеруемых с 1, итоговый балл равен `1 / (60 + r_BM25) + 1 / (60 + r_dense)`. Оба рейтинга охватывают всех кандидатов языка запроса с равным весом. Сортировка при равных баллах сохраняет порядок по возрастанию `chunk_id`. Тот же алгоритм применяется к zero-shot и LoRA. [Cormack, Clarke и Büttcher, SIGIR 2009](https://doi.org/10.1145/1571941.1572114)

## 8. Финальный TEST

Один запуск после выбора чекпойнта сравнил BM25, zero-shot BGE-M3, BGE-M3 LoRA, BM25 + zero-shot RRF и BM25 + LoRA RRF на 268 запросах. Для всех методов фиксирован набор из 3 009 чанков семи документов. Для каждого запроса берутся все кандидаты его языка, 1 692 RU или 1 317 KK. Поиск охватывает все семь документов соответствующего языка. У запроса один эталонный ID чанка.

Если эталон найден на позиции `r`, Recall@k равен 1 при `r ≤ k`, иначе 0. MRR@10 равен `1/r`, а nDCG@10 — `1/log₂(r+1)` для `r ≤ 10`. Оба балла дают 0 за промах. Все показатели усредняются по запросам в соответствующей группе, а общий результат взвешен по числу запросов RU и KK. Результаты описывают качество на семи документах и clean-подвыборке. Ограничения включают дисбаланс языков, единственную gold-метку на вопрос и возможные расхождения между редакцией документа и QA. [Полные метрики TEST](test_metrics.json)
